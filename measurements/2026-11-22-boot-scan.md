# Volume scan alone vs full boot, 1M objects (#329, step 1 of #324)

In this 1M-object run, the `scan_needles` scan is **not** most of boot on Windows (`scan` took `2.234` s against `6.210` s for `boot`, or `36.0%`, with `1,000,000` `read_calls`).

Run [44990360137](https://github.com/iskandarnorazli/Awanfs/actions/runs/44990360137) on GitHub-hosted runners (`ubuntu-latest` and `windows-latest`), 1,000,000 objects of 64 bytes (`4,215,516,840` bytes in 1 volume). `boot_bench scan` opens each `volume_*.dat` first (`VolumeManager::open`, which runs its initial recovery scan) and then times `VolumeManager::scan_needles` alone and counts `WorkCounters::disk_read` calls. `scan` runs right after `fill` with no page-cache drop, so `scan` and `boot` (warm) both read from warm OS page cache; only Linux `boot_cold` drops the page cache first.
